# Session Log

A running, append-only log of what changed in each work session on
STACKUP, and what was decided but not built. Purpose: the next session
(human or agent) should be able to read this instead of re-deriving
context from the diff history, and should not assert the project's status
without checking it here first — `README.md`'s Status section and
`docs/operations/production-readiness.md` are kept in sync with this log,
but this file has the narrative/decisions that those two don't.

Newest entry first. Each entry: date, what shipped (with PR numbers where
applicable), what was explicitly decided against or deferred, and what's
still open going into the next session.

---

## 2026-08-20 — Post-launch UX fixes + credential rollout

**Context**: Phases 0–9 (the full original roadmap) were already complete
and merged before this session started. This session was real user
feedback against the live product, plus finishing the production
credential setup that Phase 9's readiness checklist had left pending.

**Shipped (PR #11, merged)**:
- Editable display name (`full_name`) — backend migration
  `0008_user_full_name` (applied by hand to production Neon, see below),
  fastapi-users schema extension, a form field at registration, and an
  inline editor on the account home for users who registered before this
  existed.
- Inline edit/delete for cost items (`costs-list.tsx`) and applications
  (`application-header-actions.tsx`) — the "tambien se tiene que poder
  editar eliminar" request.
- Fixed 4 remaining English-string leaks (nav labels, application tabs,
  cost form field labels) — the UI is fully Spanish now.
- Fixed mobile tap-to-select (`user-select: none` on buttons/links/tabs).
- Seeded realistic demo data (applications "Cuadra"/"Stackup", ~12 cost
  items mixing USD/ARS, two LLM vendors) directly into the user's real
  production workspace, at their explicit request, so they could see the
  UI populated like the reference mockup instead of an empty state.
- CI caught one real regression before merge: the i18n fix renamed the
  cost form's "Vendor" label to "Proveedor" but the Playwright e2e test
  still selected by the old label — fixed same-session.

**Shipped (PR #12, merged)**: dashboard fixes from a second round of
feedback —
- Category/by-application/by-vendor breakdowns were filtered to only the
  workspace's primary currency, so a workspace mixing USD and ARS costs
  silently lost the ARS ones from every chart except a small top-line
  chip. Now each breakdown renders once per currency actually in use.
- Dates (cost-history changes, expense payments) were raw ISO
  `YYYY-MM-DD` strings, read backwards by an es-AR user expecting
  day/month/year. Added `formatDate` (`apps/web/lib/format.ts`), applied
  everywhere a bare date was shown.

**Production credential rollout** (dashboard actions, not code — see
`production-readiness.md` for current state): Cloudflare R2
(`stackup-evidence` bucket, scoped API token), Resend, GitHub OAuth App,
and a Redis Cloud free-tier database were all set up and configured.
`ENVIRONMENT` flipped `staging` → `production` on `stackup-api`.

**Decided against / deferred**:
- `stackup-worker` (the daily `auto_end_expired_costs` job) was **not**
  deployed. Render's free tier doesn't include Background Workers, and
  the user declined to pay for one right now — the job is a convenience
  (manually marking a cost "ended" already works), not a correctness
  gap. `REDIS_URL` currently sits unused on `stackup-api` as a result. A
  free alternative was proposed (a protected endpoint on `stackup-api`
  triggered by an external free cron pinger) but not built.
- An i18n toggle (read the UI in English) — explicitly out of scope for
  now, revisit later by request.
- Renewal/expiry alerts (warn before a cost's `end_date`, not just
  silently auto-end it) — real gap the user asked about ("las alertas de
  vencimiento... estan?"). Not built. Open scoping questions: how many
  days of advance warning, and which channel (email via Resend, in-app,
  both). Blocked on the same "something needs to run on a schedule
  without a paid worker" building block as the item above — solve that
  first, then build alerts on top of it.
- Workspace-rename and multi-currency-per-cost were reported as missing
  by the user but turned out to already work (Settings page lets an
  owner/admin rename the workspace and change its base currency; the
  cost create/edit forms already have a per-cost currency selector). The
  real gap was narrower: the *dashboard breakdowns* dropped non-primary
  currencies, fixed in PR #12 above.

**Housekeeping**: `apps/web/AGENTS.md` and `apps/web/CLAUDE.md` are
auto-regenerated by `next dev`/`next build` (Next.js 16) and get
committed to keep the tree clean — don't be alarmed if they reappear as
untracked files; that's expected, not a stray artifact.

**Going into the next session**: R2/Resend/GitHub/Redis credentials are
live in Render, but Redis is not actually driving anything yet (no
worker). If the user asks "why didn't costs auto-end" or similar, this is
why. `docs/operations/production-readiness.md` has the full current
done/pending checklist — check it before claiming something is done or
pending, don't rely on memory of this log alone since it may drift if a
future session forgets to update both.
